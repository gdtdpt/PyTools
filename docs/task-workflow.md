# PyTools 需求工作流与上下文续接

本约定用于让任何 AI 代理或协作者在换机器、换会话、丢失聊天上下文后，仍能从仓库文档恢复当前工作。`docs/project-plan.md` 记录阶段级推进；本文件约束单个需求从提出到完成的交付流程。

## 核心规则

1. 用户提出新需求后，AI 代理先不修改源码、配置或样式，先创建或更新 `docs/active-task.md`，写清实现步骤、说明与验证方式。
2. 用户反馈缺陷时，不新增独立的“问题诊断”记录；直接修订所属任务的方案、实现步骤和验证方式，然后继续修复。
3. 缺陷反馈表示原设计思路或实现计划需要修正；`docs/active-task.md` 只保留修正后的设计，不保留“发现问题、准备修复”的过程叙述。
4. 需求确认与开始编码是两个独立阶段：用户确认需求后，先把方案修订到正确无疑并标记“待方案确认”；只有用户明确确认开始编码后才改源码。用户确认缺陷修复或明确说“直接开始”时，也必须在动手前把修正后的方案和进度写入 `docs/active-task.md`。
5. 每完成一个可检查步骤，更新 `docs/active-task.md` 的清单状态、已改文件和验证结果。不要等全部完成才补写。
6. 实现中产生的用户决策、环境限制、阻塞原因和临时结论都要写入当前任务文件；聊天记录不能作为唯一上下文。
7. 进入 `待用户验收` 是硬门槛：任务文件必须提供可直接照做的用户验收步骤，写清前置条件、步骤化操作、每步通过标准、失败时的记录方式；如验收依赖测试数据，必须同时提供数据的来源、准备方式和清理方式。同一轮最终回复也必须完整给出这些步骤，不能只报告自验证结果。任一项缺失时状态保持 `进行中`。
8. 用户验收前，任务状态必须是 `待用户验收`；用户确认通过后才允许标记 `已完成`。
9. 任务完成后，在 `docs/task-log.md` 追加摘要和提交号，再把 `docs/active-task.md` 重置为“无进行中需求”。

## 续接会话入口

新会话按顺序读取：

1. `AGENTS.md`：硬性不变量与协作底线。
2. `docs/conventions.md`：编码、样式与 Git 约定。
3. `docs/active-task.md`：当前需求、步骤与最新进度。
4. `docs/task-log.md`：历史结论和提交号。
5. 必要时读取 `docs/project-plan.md`、`git log`、`git status` 和 `git diff`，但不得跳过当前任务文件。

如果 `docs/active-task.md` 显示 `进行中`，先按其中的下一步继续；不要凭记忆重写方案。需求或缺陷反馈改变交付目标时，直接更新方案和步骤，使其始终表示当前应实现的设计。

## 当前任务文件模板

`docs/active-task.md` 每次受理需求时按以下结构填写：

```markdown
# 当前任务

状态：待用户确认
更新时间：YYYY-MM-DD

## 需求

用一段话记录用户需要什么，保留关键原文含义。

## 目标

- 需要交付的可验收结果。

## 非目标

- 明确不做什么，避免扩大改动。

## 现状

- 相关文件的当前行为、已知限制和最近结论。

## 方案说明

说明关键改动点和选择理由；涉及外部工具或系统能力时要写清兼容性。

## 实现步骤

1. [ ] 步骤一
2. [ ] 步骤二

## 验证

1. 命令验证：命令与预期输出。
2. 人工验收：进入 `待用户验收` 时提供可直接照做的用户验收指引，包含前置条件、步骤化操作和每步通过标准；如需测试数据，一并说明来源、准备方式与清理方式。

## 进度记录

| 时间 | 状态 | 说明 |
|---|---|---|
| YYYY-MM-DD | 待用户确认 | 初始方案 |

## 相关文件与结论

- `src/main/app-loader.js`：记录改动原因和结果。

## 阻塞与待确认

- 没有阻塞。
```

状态只允许：`待用户确认`、`待方案确认`、`进行中`、`待用户验收`、`已完成`、`已阻塞`、`无进行中需求`。`待用户确认` 表示需求尚未确认，`待方案确认` 表示方案已修订完毕、等待用户确认开始编码。`已完成` 只表示工作流中的记录归档状态，最终交付状态以用户确认结果为准。

## 任务日志

`docs/task-log.md` 使用倒序表格，每行至少包含日期、任务、提交号、状态和关键结论。提交号用于跨机器回溯精确代码，不要只写“已修复”。

## 例外与冲突

- 用户明确要求“先改代码”时，AI 代理仍应先创建最小任务记录，再实现。
- 用户报告当前任务缺陷时，视为要求继续修复；先修订任务设计，再直接实现。
- 需求紧急且文件无法创建时，先告知用户原因，恢复能力后立即补录。
- 本文件与 `AGENTS.md` 冲突时，安全约束和 Electron 兼容性约束以 `AGENTS.md` 为准。
