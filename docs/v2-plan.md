## 1. 从 v1 继承的需求（重写验收清单的来源）

- **V2-A 性能与焦点**：呼出延迟（v1 根因：helper 每次 spawn、剪贴板全量重编码缩略图、四段串行）；目标机焦点恢复（v1 根因：capture 1s 超时静默放弃 + 无重试）。native 重写后 capture/restore 直接走 Win32，无 helper 进程；缩略图按记录 id 缓存。
- **V2-B UI 精致化**：以 Listary 为质感参照，间距/阴影/圆角/动效/字重/状态反馈六维自查，每轮截图过目。
- **V2-C 列表交互**：真分页 → 连续滚动列表；Ctrl+J/K 逐条、Ctrl+N/P 步进 N 条（可配）、滚轮/滚动条全量可达；数字键 1-0 映射当前可视区（角标锚定可视区，滚动后重编号；2026-10-30 用户验收定案）。
- **剪贴板性能**（v1 遗留诊断）：呼出时禁止全量重编码，缩略图必须缓存（按 id，upsert 失效）。

## 2. 目标机硬指标（重写验收线）

| 指标 | v1 (Electron) 现状 | v2 目标 |
|---|---|---|
| 冷启动到可呼出 | 弱机 2-4s | **<1s** |
| 主热键呼出（驻留态） | 弱机 100-300ms | **<50ms**（体感即时） |
| 剪贴板呼出（44 图历史） | 秒级（全量重编码） | **<100ms**（缩略图缓存） |

| 部署 | 220MB 目录 | **单 exe（<5MB）+ 数据文件** |
| 内存驻留 | 200MB+ | <80MB |

## 3. 设计分叉（2026-10-30 全部拍板）

### ① UI 框架：WPF ✅

- **选定 WPF**（2026-10-30 用户确认）。理由：V2-B 精致化、V2-C 连续滚动列表、动效、200% 高 DPI 四个核心需求全是 WPF 内建能力主场；WinForms 的启动/内存微弱优势在目标机硬指标里留有余量、不构成差异。
- 代价知悉：零三方依赖 = 无现成主题库，样式手工 XAML（令牌集中管理）；XAML 实现由 AI 承担，用户负责视觉验收。

### ② 工具面板形态：全部原生重做 ✅

- **选定原生重做**（2026-10-30 用户确认）：九个工具全部为 WPF 视图，与壳同栈同进程；不引 WebView2，保持单 exe 零部署。

### ③ 数据与配置兼容 ✅（默认方案无异议）

- `custom-apps.json` 格式沿用（v1 登记条目直接可用）；`config.json` 键名尽量沿用。
- 剪贴板历史数据（json + images/ 目录）沿用格式，v2 首启直接读取。

## 4. 里程碑草案

- **M0 计划定稿**：本文档三个分叉拍板；v1 功能清单盘点成重写验收矩阵（每功能：v1 行为描述 → v2 验收标准）。
- **M1 壳骨架**：全局热键、托盘、无边框呼出窗、失焦隐藏、Win32 前台 capture/restore（含采样验证 + 重试）、单实例、Esc 收起。验收：三组耗时基线 + 目标机焦点实测。
- **M2 启动器**：应用扫描、搜索（含拼音首字母，v2 新增可选）、连续滚动列表（V2-C 全量键位）、应用启动（含启动参数）、设置窗口、右键登记（HKCU 注册表，逻辑与 v1 相同）。
- **M3 剪贴板历史**：Win32 剪贴板监听、文本/图片落盘、缩略图缓存、呼出选择回填。
- **M4 AI 工具集**：ai-ocr（截图 + 调用）、翻译、正则、命名等逐个移植（HttpClient + 本地 key 文件沿用 ai-local.json 机制）。
- **M5 收尾**：图钉、环境切换等 v1 长尾功能 + 目标机整包验收（单 exe + 数据文件拷贝部署）。

每个里程碑沿用既有闭环：设计确认 → 编码 → 自验（含 UI 截图自验）→ 用户真机验收 → 提交。
